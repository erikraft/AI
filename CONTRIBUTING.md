# Contributing to ErikrafT AI

Thank you for considering a contribution!

## Before you start
- Search existing issues and pull requests before opening a new one.
- For bugs, use the [bug report template](https://github.com/erikraft/AI/issues/new?template=bug_report.yml).
- For larger changes, open an issue first to discuss the scope and avoid duplicated work.
- Be respectful and follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Pull requests
1. Fork the repository and create a focused branch from `main`.
2. Keep changes scoped to one problem or feature; avoid unrelated refactors.
3. Preserve existing behavior unless the change explicitly intends to alter it.
4. Test affected paths. For frontend changes, check Portuguese (Brazil) and English, responsive layouts, keyboard access, and browser-console errors where applicable.
5. Never commit secrets, credentials, access tokens, private user data, or generated environment files.
6. Describe the problem, solution, testing performed, and known limitations in the pull request.
7. Link related issues and include screenshots for meaningful UI changes when useful.

## Bug reports and feature requests
Provide reproduction steps, expected and actual behavior, and relevant environment details. Remove private information from logs and screenshots. Do not report credentials or security vulnerabilities in public issues; use a private reporting channel supported by GitHub if one is available.

## Development notes
- Keep the interface bilingual and maintain accessible labels and controls.
- Do not claim a model or provider feature works unless it has been tested against the actual runtime.
- Explain the need before introducing paid services or new runtime dependencies.
- Run relevant checks and state honestly which checks were and were not run.

By contributing, you agree that your contributions may be distributed under the repository's existing license. If no license applies to a particular contribution, clarify that before submitting it.
